## 改动范围

## 修改的意义（为什么这样做）

1. **数据真实性**：实测 `de441_compact.bin` header：`jd_start=-105205`（J2000-7000 = 公元前5000），
   `jd_end=3547295`（J2000+3000 = 公元5000）。之前「对称 ±5000」右端（公元5000~7000）**超出星历文件**
   → `getState` 返回 null → `spkApplied=false` → 行星/月球**静默降级 Meeus 外推**（公里级、月球无潮汐项）。
   对齐后 **UI 轴 = DE441 覆盖 = 全程真实星历、零降级区**。
2. **米兰科维奇门控内移**：覆盖内不叠加黄赤交角/偏心率示意扰动，只在超出覆盖时才混入展示用示意，更诚实。
3. **默认深时开启**：打开即停在今天实时，但时间轴已给出公元前5000~公元5000 的真实可导航区间；深时按钮默认高亮。
4. **配套文案/标签/成就/引导全同步**，避免用户可见文字与代码口径不一致。

## 是否需要修改 —— 需要；3 处全部已修复（2026-08-30）

### ✅ 已修复 1（确凿 bug）

**日期输入守卫仍用旧 ±50000 上限**：`applyDate()` 用 `DEEP_TIME_DAYS (=18262500 天 = ±50000 年)` 做越界 guard，
并提示"当前轨道模型支持约 ±5 万年"。但 UI 轴现在只到 ±5000（公元前5000~公元5000）。

- 后果：用户输入「公元 10000 年」能通过 guard，却被 `clamp` **静默压到公元 5000**；且提示文案与真实能力不符
  （DE441 根本不覆盖 ±5 万年）。
- 修复：`applyDate` guard 改为
  `nextJd < J2000 + AXIS_MIN_DAYS || nextJd > J2000 + AXIS_MAX_DAYS`；
  提示改为"当前星历覆盖约 公元前5000~公元5000；超出范围请改用专业精密星历。"；
  删除已无用的 `DEEP_TIME_DAYS` 常量。`node --check app.js` 通过。
- 这正是项目日志（2026-08-27 收尾复核）自己总结的教训"改范围类常量后必须跨文件 grep 所有魔法数字同步"——
