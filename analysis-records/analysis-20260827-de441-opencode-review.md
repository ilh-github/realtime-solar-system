## 二、P0：J2000（默认时间）附近行星插值失真 9 万 km

### 现象

`getState(2451545.0)` 的 EMB 位置 `|earth-emb| = 107313 km`（正确应 ~4890 km）。交叉验证（2026-08-26）却通过（4.64 km）——因为 2026 年不在 J2000 附近。

### 根因（已实测定位）

生成脚本 `build_segments` 的分段边界是 `[-5000y, -150y, 0, +150y, +5000y]`，其中 **`0`（即 J2000）被当作切分点**，把近期段拆成 `[1850..2000]` 和 `[2000..2150]` 两段。

每段独立做 natural cubic spline（端点二阶导数强制 =0）。J2000 恰好落在段边界上，成为**段的端点**，端点条件 `c[n-1]=0` 在边界附近引入严重插值失真。

实测（EMB y 分量，7 天步长）：

| 查询点 | 段 2 截断在 J2000 | 整段（J2000 在中间） |
|--------|------------------|---------------------|
| JD 2451500（J2000-45天） | 65.8 km | 44.8 km |
| JD 2451530（J2000-15天） | 7092.8 km | 81.5 km |
| JD 2451545（J2000） | **93836.8 km** | **57.2 km** |

结论：**去掉 0 切分后，J2000 误差从 93837 km 降到 57 km**（符合 7 天步长正常误差）。

影响范围：7 天步长的行星（EMB/金星/火星/木星等）在 J2000 ± 约 15 天区间失真；月球/地球（1 天步长）J2000 本身是采样点不受影响，但 ±0.5 天附近也失真。

### 修复

`generate_de441_compact.py` 的 `build_segments`：把边界从
```python
boundaries = [-far_limit, -near_limit, 0.0, near_limit, far_limit]
```
改为
```python
boundaries = [-far_limit, -near_limit, near_limit, far_limit]
```
（去掉 `0.0`，近期段 `[-150y, +150y]` 合并为一段，J2000 落在段中间）。重新生成 `de441_compact.bin` 即可。

> 附带说明：`±150 年` 的边界（1850/2150）仍有步长切换（7 天↔30 天），边界附近约 1 个步长（30 天）存在轻微失真，但远离默认视图，可后续用「段间重叠」优化。

## 三、范围偏差：-3000~+7000 而非 -5000~+5000

### 现象

`de441_compact.bin` header 实测：`jdStart=625295`（对应 **-3000 年**）、`jdEnd=4277795`（对应 **+7000 年**）。

用户需求是「公元上下 5000 年」= **公元前 5000 到公元 5000（天文纪年 -5000~+5000）**，对应 JD `[-105205, 3547295]`。

### 根因

生成脚本用 `jd_start = J2000 - years*365.25`（**J2000 为基准**），即「公元 2000 前后各 5000 年」= -3000~+7000。这是交接文档里「±5000 年」基准点没写清的歧义（正文写天文纪年 -5000~+5000，但代码示例用 J2000 基准）。

结果：**缺少公元前 5000~3000（2000 年），多出公元 5000~7000（2000 年）**。实测 `getState(-105205)`（-5000 年）返回 null。

### 修复（需确认）

基准改为「公元 0 年前后 5000 年」：
```python
jd_start = J2000 - 7000 * 365.25   # 公元前 5000 年
jd_end   = J2000 + 3000 * 365.25   # 公元 5000 年
```
（或等价地，`range_years` 语义改为「公元纪年 ±5000」）。
