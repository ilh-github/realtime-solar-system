# 现有实现审计记录

## 2026-08-21 · 已完成项与本轮修复

### 已完成的目标

- 主视图具备太阳系行星、太阳、地球、月球和主要卫星的轨道可视化。
- 支持日心/地心两个参考系，参考系按钮和初始锚点统一为日心。
- 支持小时级 UTC/CST 输入，并提供“保存并定位”按钮；天文年文本输入支持公元前日期。
- 默认自动历法为 1582-10-15 前儒略历、之后格里高利历，也可手动选择全程格里高利历或全程儒略历。
- 输入时间先转 UTC JD，再用 NASA/Espenak `ΔT` 近似转 TT JD，轨道模型内部统一使用 TT。
- 页面提供 `window.__ephemeris` 只读验证接口，包含 JD 正反算、`ΔT`、当前时间转换和行星/月球位置函数。
- Service Worker 版本与脚本查询参数已更新到 `v64`，源码 ZIP 包含 `index.html`，解压后可直接双击运行。

### 本轮发现并修复

1. “今日”、开场动画、今夜天象和 `.ics` 导出曾把当前 UTC 直接当作 TT，造成约几十秒的时间尺度偏差。现在统一通过 `currentTtJd()`；`.ics` 写出时再从 TT 转回 UTC。
2. 流星雨极大扫描的年初种子曾直接使用 UTC JD，现在先转为 TT JD，再进入同一套轨道计算。
3. `jdToCivil()` 在月末 23:59 附近四舍五入到次日时会递归调用自身，部分输入会触发栈溢出。现在显式处理分钟进位和月/年进位。
4. 深时提示仍写“±200 年外推”，与当前 ±5000 年展示修正阈值不一致，已改成明确的 ±5000 年说明。
5. 主页面跳转地面观星页时曾把内部 TT 直接写入 `sky.html#...&jd=`；`sky.js` 将该值按 UT 解释，会产生约一 `ΔT` 的时间偏移。现在跳转前用 `ttJdToUtcJd()` 转回 UTC JD，观星页再按自身流程转 TT。

### 回归结果

- `2000-01-31 23:59 + 0.0006 d` 正确转换为 `2000-02-01 00:00`，不再栈溢出。
- `2000-01-01 12:00 UTC` → `JD(TT) 2451545.0007392806`。
- `2024-04-08 20:00 UTC` → `JD(TT) 2460409.3341903244`，`ΔT ≈ 74.03 s`。
- `-0199-04-08 00:00 UTC` → `JD(TT) 1648470.6478758652`，`ΔT ≈ 12776.49 s`。
- 新页面加载 `app.js?v=63`，无新增控制台错误；源码打包、`node --check` 和 `git diff --check` 均通过。
- 浏览器回归：初始日心按钮与日心锚点一致；保存 `2024-04-08 20:00 CST` 后面板关闭且显示时间保持；直接关闭面板也保持新时间；`-0199-04-08 00:00 UTC` 可显示；`sky.html` 接收 UTC JD 后显示对应北京时间。
- 关闭星历面板现在也会先提交一次当前输入，覆盖原生日期控件延迟派发最终变更事件的情况；非法输入仍显示格式错误提示，不会改变当前已生效的 JD。

### 仍需明确的边界

- 行星位置仍是 JPL SSD 近似根数 + 开普勒两体模型，不是 DE440/DE441 精密星历；当前已知现代日期地球位置误差约数千公里量级。
- 公元前日期的 `ΔT` 来自历史近似模型，不是观测值；古代位置不能宣传为测量级真值。
- 主要卫星（除月球）仍是半长轴/周期/偏心率简化轨道；若要专业级卫星位置，需要接入各自 SPICE/PCK 或 HORIZONS 数据。
- 主页面以 TT 计算；主页面进入 `sky.html` 的当前时刻跳转已转换为 UTC JD，但 `sky.html` 自身仍有独立的 JavaScript `Date`/Unix 时间输入路径，且其 `ΔT` 近似只覆盖现代邻域。月球车和部分历史/发射场辅助逻辑也仍有独立时间路径；若要求所有页面共享同一时间尺度，需要下一阶段抽取公共时间模块。
- 天象扫描当前明确覆盖 1900—2100；深时轨道展示不等于深时日食/历法事件精密计算。
