# 核心三体阶段交接记录

## 本轮目标

首屏先验证太阳、地球、月球三者的关系和显示算法。其他行星、卫星、彗星、航天器和环境效果保留在代码与星历计算中，但默认不抢占视图。

## 已完成

- `app.js` 增加首屏最小显示状态：默认显示太阳、地球、月球；月球使用现有 Meeus 月球模型和地月质心修正。
- 日心模式保留地球绕日轨道线；地心模式新增太阳相对地球的前后各一年视轨，按 TT 重新采样地球质心位置，不是简单平移日心椭圆。
- 其他行星轨道线、彗星、航天器、日球层顶标签默认隐藏；选择其他对象后退出最小状态并恢复完整对象显示。
- `index.html` 将小行星带、柯伊伯带、卫星、星座连线、全景雷达的默认开关关闭。用户仍可手动打开。
- 时间输入、UTC/TT、历史日期、`window.__ephemeris` 验证接口和源码打包保持不变。

## 当前边界

- 行星仍使用 JPL SSD/Standish 近似根数加开普勒模型，不是 DE440/DE441 精密星历。
- 月球是 Meeus 60+60 项近似；公元前 `ΔT` 是历史估计。
- 默认隐藏只影响渲染，不代表其他天体的轨道数据已经达到专业精度。

## 2026-08-21 · 三体坐标合同与不变量校验

- `window.__ephemeris.threeBodyStateKm(jdTt)` 现在统一返回 `emb`（地月质心日心坐标）、`earth`（地心日心坐标）、`moonGeo`（地心月矢量）、`moon`（月球日心坐标）和 `sun`。
- `window.__ephemeris.threeBodyResidualKm(jdTt)` 返回两条独立残差：
  - `earth + μ·moonGeo - emb`，验证地月质心修正；
  - `moon - earth - moonGeo`，验证月球日心/地心坐标闭合。
- 两条关系只包含浮点加减，理论误差为机器精度量级；它们不代表模型相对 DE440/DE441 的物理误差。
- 通过 `node --check app.js`、`git diff --check`；源码打包回归继续使用 `sh package-source.sh`。

### 解释边界

接口的 `jdTt` 必须是 TT 儒略日。民用输入应先调用已有的 `parseDateToTtJd()` 或 `utcJdToTtJd()`，不要把 UTC JD 直接传给三体位置函数。

## 2026-08-21 · HORIZONS 三体对照

本次使用 JPL HORIZONS API 的 DE441 几何向量作为对照：太阳中心地球（目标 399、中心 `@sun`）和地心月球（目标 301、中心 `@399`），黄道 J2000 坐标、无光行时修正、km。现代时刻以程序的 TT JD 作为 HORIZONS 的 TDB 查询历元；TT/TDB 的亚毫秒级差异远小于本模型误差。历史样例沿用混合儒略/格里高利历。

| TT JD / 民用样例 | 地球日心位置误差 | 地球角误差 | 月地矢量误差 | 月球角误差 |
| --- | ---: | ---: | ---: | ---: |
| 2451545.000000 / J2000 | 2,006 km | 2.76″ | 5.0 km | 1.66″ |
| 2460409.334190 / 2024-04-08 20:00 UTC | 5,639 km | 7.45″ | 5.9 km | 3.11″ |
| 1648470.647876 / -0199-04-08 00:00 UTC | 42,105 km | 56.42″ | 92.5 km | 47.08″ |

结果确认：月球 Meeus 模型在现代日期的地心距离误差保持在数公里量级；地球 Standish 近似根数的误差为数千公里，公元前 200 年外推扩大到约 4.2 万公里。历史样例还叠加 `ΔT` 估计不确定性，因此不能解释为 DE441 精度。

## 下一对话优先级

1. [x] 暴露太阳、地球、月球的统一坐标接口和三体代数不变量。
2. 用 JPL HORIZONS/NAIF SPICE 对照 J2000、当前日期、日食日期和公元前样例，输出位置误差表。
3. 明确时间尺度合同：输入 UTC/CST，内部 TT，地面观星页面消费 UTC；所有页面统一走同一转换函数。
4. 再逐项恢复其他行星、卫星和环境显示，每恢复一类就增加独立回归。
5. 最后再考虑 DE440/DE441 或 SPICE 数据包，避免把近似模型误称为“真实测量值”。
